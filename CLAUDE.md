# Tishreen Mall — Workspace-Regeln

- **Bei offenen Fragen zuerst fragen, nicht machen:** Sobald eine Aufgabe eine ungeklärte Produkt-, Scope- oder Architekturfrage enthält (Anforderung mehrdeutig, Docs schweigen oder widersprechen sich, mehrere sinnvolle Varianten), stellt die KI erst die Frage(n) an Mohamad — mit kurzen Optionen und einer Empfehlung — und setzt erst nach der Antwort um. Nur rein technische, aus Docs/Code eindeutig ableitbare Detailentscheidungen dürfen ohne Rückfrage getroffen werden (dann im Ergebnis benennen).

- **Tickets nur über die Skill `ticket`** (`.claude/skills/ticket/SKILL.md`): jedes Anlegen, Ändern, Schließen oder Verknüpfen von GitHub-Issues läuft über diesen Workflow — nie über rohe `gh issue`-Befehle daran vorbei. Abhängigkeiten (`Blocked by:` / `Blocks:`) immer auf **beiden** Tickets pflegen; Label `blocked`, solange ein Blocker offen ist.
- **Nach der Implementierung eines Tickets** immer die Übergabe aus Skill-Abschnitt 4 liefern: Commit-Text + `git add`/`git commit`-Kommando mit Dateiliste, PR-Titel und PR-Beschreibung.
- **Kanonische Docs & Regeln** liegen in `tishreen-handoff/tishreen-handoff/` und werden ins GitHub-Wiki gespiegelt (`scripts/sync-wiki.sh`, GitHub Action `sync-wiki`). Änderungen an diesen Quellen → committen + pushen, das Wiki zieht automatisch nach; nie direkt im Wiki editieren. **Das Wiki ist die maßgebliche Referenz** — nach jeder Änderung und jeder neuen Entscheidung aktuell halten: Entscheidungen als ADR in `docs/adr/` ablegen (Vorlage `0000-template.md`), sie werden automatisch mitgespiegelt.
